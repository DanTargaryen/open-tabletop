# 璀璨宝石 · 宝可梦特别款

已发行《Splendor: Pokémon》特别版规则的非官方网页实现。支持 2–4 个座位，单人对战本地 AI，或使用同一个 Node 服务与好友联机。与经典版不同：本作使用进化、特殊宝可梦卡与 18 分终局，没有贵族。

在仓库根目录运行 `npm start`，打开 `/games/splendor/index.html`（单人）或 `/games/splendor/online.html`（好友房）。没有 npm 运行依赖。

## 怎么玩

1. 选择人数与昵称。单人模式的其余座位为 AI；好友房由玩家准备后开局，房主可选择用 AI 补齐空位。
2. 点击供应区选择精灵球并确认拿取，或点击宝可梦卡查看费用、捕捉或预留。点击一至三级牌库可盲预留。
3. 超出十枚球时先选择归还。若符合条件，右侧会出现进化选项；每回合至多一次，也可以放弃。进化可以使用自己预留的下一阶卡。
4. 达到十八分后补完当前轮，按奖杯、进化次数、场上宝可梦数量依次比较。完局后可以再开一局。

大师球可以替代普通球。捕捉弹窗中的“调整支付方式”允许保留某种普通球，改用大师球支付。特殊卡的必需大师球不能由普通球或永久加成替代。

页面下方的个人区域显示六种球的持有数量、总数与超额提示，并单独列出永久加成。默认使用紧凑布局：公共展示区与操作面板并排，个人区横跨牌桌，已捕捉宝可梦使用一至两排插画小卡，预留卡独立显示。已支付过的捕捉费用收进完整详情，点击卡牌可看大图和全部数值，已捕捉卡也可回放入队效果。右上角“舒展布局”恢复大卡，布局偏好单独保存，不改变对局。

1117×759 桌面测试窗口可同时显示 14 张展示卡、持球、20 张已捕捉卡和 3 张预留卡。窗口较窄或较矮时保留页面滚动；手机的队伍卡横向浏览，特别多的卡牌或进化选项可在各自区域内滚动。冒险记录可展开查看。

## 捕捉反馈

捕捉成功后，角色会弹出并飞向队伍，随后显示获得的永久加成或奖杯；进化显示新旧卡替换后的净收益。对手的捕捉以较轻的提示展示。动效不拦截点击，也不改变回合。

点击自己已经拥有的卡，可以选择“回放加入队伍动效”，无需再次捕捉或消耗筹码。系统启用减少动态效果时，使用静态成功提示；音效遵循页面原有开关。首次加载、刷新恢复、重复状态和被拒绝的动作不会自动播放成功效果。

## 运行与联机

`/api/splendor` 是独立接口。数据保存在配置数据目录的 `splendor-rooms.json`，与扑克分开；运行数据不属于公开资源。`npm run lan` 可提供局域网访问，公网需要部署者自己的 Node + HTTPS 入口。

房间使用服务端权威状态、随机洗牌、SHA-256 身份摘要、版本检查、请求编号去重和存储 CAS。每次回复只包含当前玩家可见的信息：不发送牌库顺序、他人的预留卡身份或训练师板卡面。所有人的持球、场上卡和数量公开。

浏览器保留独立的宝可梦版命名空间。刷新恢复需要原浏览器身份和未过期房间；主动离开会撤销座位身份，并在对局中交由 AI 接手。房主离开后转交给剩余真人。所有真人离开则房间失效。房间活动 TTL 为 24 小时。

联机约定：先手随机；真人每个待处理动作限时 120 秒，超时由本地策略执行一个合法决定。AI 默认间隔 900 毫秒。推进由已认证的请求触发，无人请求时不会在后台连续代打。无合法主动作时允许跳过；三层判定仍同分时共享胜利。上述数字化约定与实体规则分开。

单人 AI 有均衡、奖杯竞速、进化三个权重配置，使用可见状态选择合法动作；不读取对手预留或牌库，不调用外部模型。它们是启发式策略，并非经过竞技强度评级的模型。

## 验证与边界

- 根目录 `npm test` 自动发现本游戏的规则、房间与真实 HTTP 测试。
- 自动对局覆盖 2、3、4 人各 12 个固定种子；逐步检查 90 张卡、精灵球、加成和分数。
- 数值卡池是 **35 / 30 / 15 / 5 / 5**，共 90 张、55 种。来源为社区转录；已核对分布和引用完整性，**尚未逐张对照实体盒**。
- 本地和静态单人都能运行。当前 Cloudflare 适配器只支持扑克联机，宝可梦接口会明确返回 503。不要将静态构建成功理解为联机后端已部署。
- 本地双浏览器验证不等于异地公网实测。现有扑克试玩站不包含本游戏。
