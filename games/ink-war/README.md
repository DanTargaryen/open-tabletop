# 墨战 · 水墨征伐

基于《墨战》公开介绍和官方截图制作的非官方浏览器玩法复现。水墨地图、墨团城池、汉字士兵、自由划选和任意目的地指挥，以原创 Canvas 绘制实现。当前版本为 `0.1.0`，支持单人本地策略 AI 与 2–7 人 Node 好友房。

## 运行与操作

在项目根目录运行 `npm start`，打开 `http://127.0.0.1:18772/games/ink-war/index.html`。好友房入口为 `/games/ink-war/online.html`。

鼠标或手指拖动框选己方士兵，再点击目的地。点击己方城池可以选中附近驻军，`A` 或“全军出击”选中全军，`Escape` 取消选择。电脑可用右键下达行军命令。士兵自动接敌、攻城；新的远离敌人的移动命令允许主动撤退。单人模式可暂停，联机同时对战不能暂停。

单人默认三国入门，仍可选择2–7国。人机难度有入门、标准、挑战：入门开局至少12秒才出征，调兵间隔至少6秒，出征至少6兵并保留约35%空闲守军；标准开局至少8秒、调兵间隔4秒、出征至少4兵并保留约20%守军。前两档已有行军命令持续执行，新兵另组远征，避免全军频繁改令；受到至少5兵围城时可在正常调兵间隔内集中防守。挑战保留原来的快速扩张与全军调度。各档兵种、城池、产兵和反击技能数值一致，不额外削弱AI属性；好友房仍使用原来的AI规则。

地图支持放大、缩小、全图与归营。电脑可滚轮缩放、中键拖动平移；手机或电脑点击“拖图”后拖动查看，再点击“调兵”恢复选兵。放大时保持字兵和墨团清晰，操作目的地按当前视角转换。

驻军会沿所属城池的一至三圈阵型持续绕城巡逻，约22.4秒一周，圈内保持均匀间距；遇敌正常交战，脱离战斗后回到巡逻阵型。出征和送兵命令取消巡逻，行军按兵种速度进行；满血最高等级城的归营士兵及空闲入营士兵也会加入巡逻。单人暂停时绕圈一起暂停，联机由共享规则统一推进并平滑显示。

城池持续生产刀、枪、剑、盾、弓，五种兵的生命、伤害、速度和射程各异。占领中立城提供更多兵源。失去最后一座城池时立即淘汰，残兵移除；只剩一个持城阵营时获胜，其余中立城在终局自动归赢家。这项终局收城是本项目实现的规则。地图有山河对峙、逐鹿原野、群山争雄三种，每局新种子重新生成分散的城池布局、河流或山隘及产兵序列；河流和山隘减速，桥面正常通行。战前从三张候选兵法中选择一张，本局生效。八种兵法涵盖募兵、速度、伤害、防御、弓兵、恢复、攻城和生命。

地图宽高随参战人数从两人 1200×760 增长到七人 2400×1520，城市总数为人数的四倍：每国一座主城，另有三倍人数的中立城。主城分散到随机旋转的外围，中立城遍布全场，生成时保持城池间距。同一局联机玩家共享同一张地图；重赛重新生成，刷新恢复仍使用原局地图。

每座城开局都是一级，最高等级由地图种子随机分配为一级、二级或三级，每张地图都有三种上限。一级上限没有黑色虚线圈，二级上限一个圈，三级上限两个圈；圈是固定的下一等级墨团轮廓，吞兵扩建会逐渐长到对应圈大小。地图不显示地名、等级或驻军文字，当前等级由墨团大小体现。一级驻军最多16名（一圈），二级40名（两圈），三级72名（三圈）；满额暂停产兵，调走、阵亡或吞掉驻军后恢复。城池上限限制附近驻军，出征部队仍受全局700兵、每阵营普通产兵150兵的性能上限约束；技能援军允许该阵营临时达到300兵，全场仍不超过700兵，满场时援军排队入场。

选中己方士兵后点击己方城池，下达送兵命令，士兵到城后按存活部队顺序结算。未满血时每兵回复20点血量；满血且未达最高等级时，每兵增加8点基础血量上限、半径增加0.3，扩建后保持满血。吞16兵升二级，再吞24兵升三级，只有突破等级才提升驻军上限。满血且已达最高等级时不会吞兵，剩余士兵归营，满营则在圈外等候；可重新下达行军命令取消送兵。易主和投降保留等级、上限与扩建投入，血量按新阵营的守城兵法重新计算。联机由服务器结算，并对行动编号、目标城和士兵归属校验，网络重试不会重复送兵。

## 扩张平衡与自动反击

新占领城池需要5秒整备，之后才开始累计产兵。可产兵城池为1、2、3、4座时，全阵营基础总产速依次为1、1.6、2.1、2.5倍，此后每座增加0.3倍，平均分给各可产兵城。等级驻军上限仍有效。

所有2–7阵营使用同一套判断，真人和AI一致。两方存活时对比唯一对手；三方以上取“第二名城池数”和“第一名城池数减1”中较大值（第一名至少3城才参与减1）。因此多人开局单个对手第一次扩张不会给其余全场同时发技能。

- 一级：比参考对手少至少1城，持续6秒。
- 二级：仍落后，基础经济（含募兵兵法）不高于参考对手78%，持续8秒。
- 三级：仍落后且城池不超过参考对手一半，同时有效兵力低于最强对手60%，或者20秒内丢掉至少2城，持续8秒。

另有独立绝境救援“神凌”：发生失城且只剩一座城池时必定触发，降下200名永久可控士兵，可以调动与吞兵养城。开局一城、失去全部城池与主动投降不触发；每个阵营每局一次，不受三级随机反击是否用完和20秒冷却影响。援军优先入场，通常当帧全部降下；战场达到700兵上限时，尚未入场的部分优先等待空位，数量不丢失。此援军允许突破普通技能300兵的阵营限制，但不突破全场700兵预算。界面显示神凌战报和短暂天降光束。

各级按顺序自动随机触发，每级每人每局一次，两次至少间隔20秒。条件消失就清空该条件的计时，不因单纯吞兵升级造成兵力减少而触发。技能名单如下：

| 等级 | 技能 | 效果 |
| --- | --- | --- |
| 1 | 乡勇应召 | 8名可控援军 |
| 1 | 轻装疾行 | 全军移速+35%，12秒 |
| 1 | 募兵急令 | 产兵+50%，10秒，仍受满营限制 |
| 1 | 先登夺城 | 对中立城伤害翻倍，12秒 |
| 2 | 援军入阵 | 36名可控援军 |
| 2 | 破釜沉舟 | 全军回血，攻击与攻城+60%，12秒 |
| 2 | 天雷荡寇 | 己方一城周围240范围敌兵损失55%当前血量、减速8秒；无人围城时不抽中 |
| 2 | 声东击西 | 24名不可控奇兵，快速攻最近敌城，15秒消散 |
| 2 | 坚壁清野 | 各己城回血30%、减伤60%，12秒 |
| 3 | 百鬼夜行 | 各方包括施放者随机消灭60%现存士兵，城池不受影响；全场25秒内不重复抽中 |
| 3 | 急行军 | 120名不可控、不可吞兵的3.5倍速突击兵，攻最近两座敌城，20秒消散 |
| 3 | 神兵天降 | 随机己城旁100名永久可控援军，可以吞兵养城 |

援军分批每规则帧最多10名入场，受全局兵力预算约束；急行军与奇兵从释放时开始计时，超时的排队援军一并消散。突击兵占领目的地后守城，无法手动调动。反击信息通过共享战报与提示显示，联机由服务器统一随机与结算，刷新后保留已用等级、效果和剩余时长。

## 好友对战

单人和好友房的新对局均从每阵营 0 名士兵开始，保留主城，由城池持续产兵。普通城池约 1.7 秒产出首名士兵，募兵令会加快速度；没有士兵但仍有城池时不会被淘汰。首页七国列阵是独立的示意插画，不代表开局兵力。

房主选择人数、地图和 AI 数量后创建六位房间码。朋友打开同一服务器上的页面，使用邀请链接或房间码加入。AI 只能由房主明确添加，空座位不会冒充真人。所有真人选卡、在线并准备后，房主开始。2–7 个阵营同时指挥，不采用轮流行动。

同一局域网内运行 `npm run lan`，朋友打开启动输出的 LAN 地址。互联网对战需要部署这个 Node 服务，并使用同一个可访问的 HTTPS 地址。当前游戏未接入 Cloudflare Worker 的房间 API，也未发布到 README 中的现有演示域名。

页面使用每个浏览器标签独立的会话身份，刷新后恢复原阵营。断网会重连并保留席位；断线中的军队继续自动战斗与产兵，不能自动接收新命令。主动退出会投降。房主离开时迁移房主；房主离线超过 30 秒时，可迁移给在线玩家。结束后双方返回大厅重新准备，可以继续下一局。

## 服务运行边界

规则引擎由单人与服务端共享。服务端校验身份、部队归属与目的地，使用版本比较交换处理并发；每位玩家最近 128 个命令编号用于避免重复操作。实时命令不要求浏览器携带最新房间版本。

服务端通过已认证的轮询与命令按照服务器时间推进 10 Hz 模拟，页面每约 200 毫秒同步一次。无人访问时没有独立模拟定时器，恢复时最多补进 5 秒，超出时间丢弃。后台标签降低同步频率。这是小型房间运行方案，未进行大规模并发压测。

房间独立保存到私有数据目录的 `ink-war-rooms.json`，24 小时无活动过期，服务重启可恢复。沿用项目单进程文件存储，不支持多进程同时写一份数据。公开快照没有座位密钥和其摘要；战场为全部公开信息，不设置战争迷雾。全场上限 700 名士兵，普通产兵每阵营上限150，技能援军上限300，满场援军排队入场。

## 原版核对范围

已参考官方说明的自由划选、任意点指挥、字形兵种、攻占城池与卡牌决策。官方截图显示竖向宣纸战场、墨团城池、微小汉字军队、全军出击及多个阵营；本项目手机呈竖向战场，电脑展开地图。

**当前不能视为原版的完整精确复刻。** 未获取原版源码、完整卡表、关卡库、数值公式或音画资源。本项目的三类随机地图、八张卡牌、兵种数值、AI 与新增加的真人房间由本项目实现。原版战后选卡与累积养成尚未复现为持久化战役，当前选卡在每局开始前进行。原版军衔、军功、排名、皮肤、抽奖、广告与账号经济系统不在当前实现中。本版本支持二至七国混战，原版真人联机人数上限未证实。

所有界面与图形为本项目原创绘制，音效由 Web Audio 合成。背景音乐 `web/assets/ink-battle.wav` 是本项目原创合成的48秒五声音阶器乐循环，无外部录音素材；顶部独立开关，首次点击后播放，暂停或隐藏页面时停止播放。来源与未知项见 [SOURCES.md](SOURCES.md)。

## 验证

根目录 `npm test` 自动收集此游戏的规则、房间和 HTTP 测试。`npm run build:static` 包含所有公开资源；静态文件本身不提供房间服务。

浏览器验收脚本：`node scripts/check-ink-war.mjs`。可设置 `PLAYWRIGHT_MODULE_PATH` 到已安装的 Playwright 包位置；默认使用系统 Edge。脚本验证单人选兵与暂停、两份独立浏览器身份的入房与准备、同时指挥、刷新恢复及窄屏操作，截图保存在忽略目录 `_qa/ink-war/`。

画面绘制与规则帧独立：规则仍为 10 Hz，单人及联机使用坐标插值平滑行军，绘制最高 120 Hz，实际帧率受屏幕刷新率和设备性能影响。静态首页、暂停和隐藏页面停止持续绘制；字体、画布尺寸、选择或特效变化时才唤醒。墨团纹理、字兵和阴影按显示尺寸缓存，界面统计仅在内容改变时更新。同一存储中的同房间请求排队，避免并发轮询重复模拟，其他房间不受此队列阻塞。

性能验收：启动本地服务后运行 `node scripts/measure-ink-war.mjs`，可用 `INK_WAR_URL` 指定地址（默认 `http://127.0.0.1:18773`）。使用 Edge、双倍像素比例与 1×/4× CPU 条件，记录首页、七国对战及 700 兵绘制耗时；同时验证首页停止循环、120 Hz 绘制上限、单人可变状态插值与新局重置。测量结果保存在 `_qa/ink-war/performance-after.json`，设备、浏览器和同时运行的程序会影响耗时。
