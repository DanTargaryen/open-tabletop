# 添加一款游戏

合集的组织单位是 `games/<game-id>/`。先做出一款可独立游玩的游戏，再将它登记到首页目录；不需要先抽象一个通用桌游引擎。

当前唯一实现是 `games/texas-holdem/`，可参考它的文件组织。扑克的规则和接口不要求其他游戏照搬。

## 1. 建立游戏目录

选择一个稳定、小写、以连字符分隔的 `game-id`，例如 `my-game`：

```text
games/my-game/
  web/
    index.html
  server/
  tests/
  scripts/
```

`web/` 放公开的 HTML、CSS、JavaScript 和素材。浏览器入口使用 `/games/my-game/index.html`。`server/` 放服务端规则与房间逻辑；纯本地游戏可以省略。`tests/` 放行为测试，`scripts/` 仅在有开发工具时创建。

服务端模块、测试、配置和运行数据都不应通过静态路由暴露。在 `server/index.mjs` 中接入新游戏 `web/` 目录的静态映射；当前扑克的映射是显式配置的，新增目录不会自动生效。不要为省事将整个 `games/` 目录作为可下载文件树。

## 2. 做出可玩的最小版本

至少具备：清晰的开始方式、合法行动的反馈、终局或重开路径，以及回到合集首页的入口。窄屏上应能够完成主要操作。

规则逻辑尽量与界面分开，便于测试。如果包含联机玩法，服务端应校验行动、推进权威状态，并按玩家身份生成可见状态；不要把完整暗牌或其他隐藏信息发给所有客户端后再用 CSS 隐藏。

新游戏的运行数据使用独立命名空间，放入配置的运行数据目录。不要与扑克共用房间状态结构，也不要让浏览器指定服务器上的任意文件路径。

## 3. 登记到首页

编辑 `games/catalog.json`，参考现有扑克条目的字段，添加新游戏的名称、介绍和已实现入口。保留文件当前的数据结构，不要另建一份只供新页面使用的游戏列表。

例如，一款只有本地模式的游戏条目可以从以下结构开始：

```json
{
  "id": "my-game",
  "title": "我的桌游",
  "subtitle": "MY GAME",
  "description": "用一句话说明玩法。",
  "players": "1 人",
  "category": "策略",
  "version": "0.1.0",
  "solo": "/games/my-game/index.html"
}
```

`id` 应与目录名一致，`solo` 和可选的 `online` 填写实际可访问的路径。没有实现的模式省略入口，并确认首页能正确处理缺少该字段的条目。

首页通过 `/games.json` 读取这个目录，但目录登记本身不会实现静态映射、服务端接口或补齐构建逻辑。检查实际访问是否成功：

- `/` 能展示新游戏，文案与实际玩法一致。
- `/games/<game-id>/index.html` 能直接打开，刷新后仍可访问。
- 需要服务端能力时，根服务器已接入相应处理器。
- `npm run build:static` 的 `.dist/public` 包含所需公开资源。

只登记已经可以打开的入口。联机、AI、观战或其他模式没有实现时，不要显示为可用功能。

## 4. 接入服务端与可选平台

为新游戏选择独立的 API 路径，例如 `/api/my-game`，并在 `server/index.mjs` 接入。`/api/poker` 是扑克当前保留的接口，不是所有游戏必须复用的公共接口。

共享的 HTTP 处理或存储辅助代码可以按实际需要提取；牌型、回合推进等规则继续留在游戏目录中。更换存储或增加并发能力时，应先写清数据生命周期与一致性需求。

Cloudflare 是可选部署适配器。增加 Node 服务端游戏不代表它自动支持 Worker；如果声明支持该平台，还需要接入对应处理器、资源绑定和部署说明，并实际验证。

## 5. 加入验证

让根目录的 `npm test` 能运行新游戏的测试，遵循仓库当前的测试入口，不要仅在游戏子目录留下一个无人执行的命令。

有价值的验证包括：

- 行动是否合法、轮次如何推进，以及终局计算。
- 资源数量或分数守恒、边界输入与重复请求。
- 联机身份隔离、隐藏信息保护、刷新恢复与超时。
- 根服务入口与游戏页面的路由，以及静态构建后的资源路径。

界面仍需要人工操作验证。若新游戏只支持本地玩法，明确注明范围即可；不必为凑齐目录结构实现不需要的联网功能。

## 6. 准备 Pull Request

在根 README 中更新当前可玩游戏，补充新规则的简短说明或游戏内帮助。附上截图、运行步骤和实际执行的验证，说明任何仍未实现的模式。

素材必须可合法分发。第三方素材保留来源与许可，并更新 `THIRD_PARTY_NOTICES.md`。不要提交开发日志、运行数据、真实资源 ID 或密钥。

更多提交约定见 [贡献指南](../CONTRIBUTING.md)。
